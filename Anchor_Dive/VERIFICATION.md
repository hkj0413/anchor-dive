# 60Hz / 120FPS 변경 검증 — 2026-10-16

## 실행 환경
- Godot 4.7.2.stable.official.ed1daf0bf, Linux x86_64
- 헤드리스 실행: 실제 GPU 화면 출력이나 120Hz 디스플레이 성능 측정은 포함하지 않음

## 확인한 결과
1. 프로젝트 임포트 및 기본 씬 180프레임 실행: 스크립트/런타임 오류 없음.
2. 원본에 파서 호환 수정만 적용한 비교 버전과 수정 버전에 같은 물리 틱별 입력을 적용.
3. 수정 버전의 화면 상한 60FPS와 120FPS 모두 360틱의 위치·속도·탄약·공격/반동/장전 타이머·방패 상태/에너지·접지 상태가 비교 버전과 완전히 일치.
4. 사격·반동 사격·장전 이벤트가 발생한 물리 틱도 모두 일치.
5. 120FPS 설정에서 물리가 갱신되지 않은 렌더 프레임에도 캐릭터 표시 위치, 카메라 화면 중심, 시각적 조준 방향이 갱신됨을 확인.
6. 총의 시각적 조준이 같은 프레임의 카메라 좌표와 일치하고, 표시 처리가 게임플레이 조준 값을 덮어쓰지 않음을 확인.
7. 낙하 리셋 시 스폰 위치 복구와 표시 위치/보간 기록 초기화를 확인.

최종 120FPS 테스트는 360개의 물리 상태를 기록하는 동안 720회의 렌더 루프 콜백을 관찰했습니다. 이는 헤드리스 콜백 검증 결과이며 GPU 성능 벤치마크가 아닙니다. 실제 화면의 부드러움·입력 감각·120FPS 유지 여부는 120Hz 이상 디스플레이에서 확인해야 합니다.

## 비교 조건
- 물리 비교에서는 조준 방향을 오른쪽으로 고정하여 카메라 움직임에 따른 조준 차이를 제외했습니다.
- 표시용 조준과 카메라는 실제 코드대로 렌더 프레임에서 갱신했습니다.
- 입력에는 이동, 점프, 공격, 방패, 반동 사격, 장전 및 낙하 리셋이 포함됩니다.
- 원본은 Godot 4.7.2에서 그대로 컴파일되지 않아 아래 두 파서 호환 수정만 양쪽에 동일하게 적용한 뒤 비교했습니다.
  - 직접 작성한 `draw_ellipse`를 `_draw_shadow_ellipse`로 변경: 엔진의 같은 이름 메서드와 충돌 방지.
  - 트레이서의 `clamp`를 `clampf`로 변경: 실수형 추론을 명확히 지정.

## 재실행
프로젝트 폴더에서 실행합니다. `godot`는 로컬 Godot 실행 파일 경로로 바꿀 수 있습니다.

```sh
godot --headless --editor --import --quit
godot --headless --script res://tests/frame_regression.gd -- 60 result_60.json
godot --headless --script res://tests/frame_regression.gd -- 120 result_120.json
```

각 실행은 `failures=[]`와 종료 코드 0을 반환해야 합니다. 두 JSON의 `snapshots`와 `events`를 비교하면 FPS 변경에 따른 게임플레이 회귀 여부를 확인할 수 있습니다. 테스트는 프로젝트 설정 파일을 수정하지 않습니다.
